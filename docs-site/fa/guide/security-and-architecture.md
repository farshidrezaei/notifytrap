# امنیت و معماری

**NotifyTrap** به‌عنوان یک **مونو‌لیت ماژولار (Modular Monolith)** پیاده‌سازی شده که در یک فرایند دسکتاپ واحد و بدون وابستگی ابری اجرا می‌شود.

## معماری لایه‌ای در Rust (`src-tauri/src/`)

| لایه | مسئولیت |
| --- | --- |
| `domain/` | مدل‌های هسته، وضعیت‌ها، قوانین اعتبارسنجی و نوع‌های خطای دامین (`thiserror`) |
| `application/` | سرویس‌های کاربردی و Use Caseها برای شکار، مدیریت کانال‌ها و جست‌وجو |
| `infrastructure/` | پیاده‌سازی SQLite، رمزنگاری AES-256-GCM، پالایشگر HTML (`ammonia`) و سرویس Keyring |
| `services/` | سرورهای لوکال `Axum` (HTTP) و `Tokio` (SMTP) در تردهای ایزوله پس‌زمینه |
| `commands/` و `events/` | پل ارتباطی امن بین فرانت‌اند Nuxt و لایه application در Tauri IPC |

## لایه‌های امنیتی اصلی

### ۱. ایزولاسیون محتوای HTML ایمیل
بدنه ایمیل‌ها پیش از ارسال به UI توسط کتابخانه `ammonia` در بک‌اند Rust پالایش می‌شوند تا تگ‌ها و صفت‌های ناامن (مانند `<script>`، `on*`، منابع خارجی حساس) حذف شوند. سپس در فرانت‌اند داخل `<iframe sandbox="" referrerpolicy="no-referrer">` رندر می‌شوند.

### ۲. رمزنگاری Credentialها و نگهداری کلید
- کلید اصلی رمزنگاری در Keyring بومی سیستم‌عامل (`macOS Keychain`، `Windows Credential Manager` یا `Linux Secret Service`) نگهداری می‌شود.
- برای محیط‌هایی که Secret Service در سیستم‌عامل راه‌اندازی نشده باشد، مسیر fallback لوکال رمزنگاری‌شده با محدودیت سطح دسترسی فایل (`0600`) پیش‌بینی شده تا در نشست‌های بعدی همچنان قابلیت Reveal حفظ شود.
- هنگام احراز هویت دریافتی، مقایسه هش با زمان ثابت (`constant-time comparison`) انجام می‌شود.

### ۳. بدون ارسال به بیرون (Zero External Delivery)
هیچ منطقی برای فوروارد ایمیل، رله SMTP یا فراخوانی URLهای خارجی وجود ندارد. شما می‌توانید با خیال راحت از داده‌های واقعی یا تولیدی همتاسازی‌شده در محیط توسعه بدون ریسک ارسال تصادفی به کاربران واقعی استفاده کنید.

# NotifyTrap — Internationalization (i18n) Contract

## 1. Supported Locales

| Code | Language | Name | Direction | Date/Number Locale |
| --- | --- | --- | --- | --- |
| `en` | `en-US` | English | `ltr` | `en-US` |
| `fa` | `fa-IR` | فارسی | `rtl` | `fa-IR` |

Adding a third locale requires adding a locale descriptor in `nuxt.config.ts`, creating `i18n/locales/<code >.json` matching the canonical schema, and running the i18n verification script.

---

## 2. Key Organization

All translation files live under `i18n/locales/` (`en.json`, `fa.json`) and are organized strictly by feature domain and semantic intent:

- `application.*` — App title, status labels, global actions
- `navigation.*` — Sidebar routes and landmarks
- `workspace.*` — Active workspace/project/environment switcher
- `overview.*` — Overview dashboard cards, service health, quick actions
- `inbox.*` — Unified inbox, filters, search, empty/loading/error states
- `inspector.*` — Channel-specific inspector tabs, headers, attachments, copy actions
- `workspaces.*` — Workspace list, create/edit/delete forms, confirmations
- `projects.*` — Project list, environments, forms
- `channels.*` — Channel types, credentials, reveal/copy/rotate, integration snippets
- `settings.*` — Appearance, language, server ports, database info, retention
- `designSystem.*` — `/design-system` showcase labels
- `validation.*` — Client/server form validation messages
- `errors.*` — Structured error translations mapped from backend error codes
- `common.*` — Shared unambiguous actions (`save`, `cancel`, `delete`, `copy`, `copied`, `refresh`, etc.)

Never reuse one generic key for distinct contextual meanings.

## 3. RTL / LTR Rules

- Direction (`dir="rtl"` / `dir="ltr"`) and `lang` attribute on `<html>` are driven centrally by `@nuxtjs/i18n` (`useLocaleHead()`) and synced automatically with Nuxt UI `<UApp>`.
- **Prohibited**: `ml-*`, `mr-*`, `pl-*`, `pr-*`, `left-*`, `right-*`, `text-left`, `text-right`, `border-l-*`, `border-r-*` (except inside explicitly LTR-locked technical code/payload viewers where `dir="ltr"` is semantically required for JSON/MIME/URLs).
- **Mandatory**: Logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`, `border-s-*`, `border-e-*`).
- Technical identifiers (URLs, JSON payloads, email headers, SMTP credentials, UUIDs) must explicitly set `dir="ltr"` and `font-mono` so RTL never scrambles IP addresses, ports, or code snippets.
- **Multi-Script Numeric Inputs**: Numeric and port/IPv4/phone/verification-code masks accept Persian (`۰-۹`), Arabic-Indic (`٠-٩`), and Hindi/Devanagari (`०-९`) digits natively and normalize them to English ASCII digits before sending payloads to the Rust backend (`app/utils/numberNormalization.ts` and `src-tauri/src/domain/validation.rs`).
- **Strict English & Slug Fields**: Technical fields (`slug`, `credentialIdentifier`, `targetEndpointUrl`, general ASCII keys) explicitly reject non-ASCII scripts via `validation.englishOnly` and `validation.invalidSlug` without silently swallowing invalid keystrokes.
- **Hint Popovers**: Form fields present helper hints inside compact click-to-toggle `<UPopover>` triggers (`SharedHintedFormField`) aligned with the label header so LTR and RTL grid alignment remains symmetrical.

## 4. Automated CI Validation

Run `pnpm run validate:i18n` (or `npm run validate:i18n`) on every change. The validator fails with non-zero exit status if:
1. Any key present in `en.json` is missing in `fa.json` (or vice versa).
2. Any leaf translation string is empty or whitespace-only.
3. Any node mixes object and string types across locales.
4. Any interpolation placeholder (`{name}`) differs between locales.
5. Any component/page contains obvious untranslated UI text outside `t()` / `$t()` (checked by audit rules).
